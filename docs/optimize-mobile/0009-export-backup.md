# 0009 · 加密备份导出与 CSV 导出

- **优先级**:🟢 中低(功能 / 容灾)
- **类型**:功能
- **状态**:⬜ 未开始
- **预估工作量**:M(1.5 天)

## 背景与问题
项目有完整的 **AI 导入**能力,却**没有导出 / 备份**,数据迁移与容灾缺位。换机、卸载即丢失。应提供:
1. **加密备份导出**(推荐):导出受密码保护的加密文件,可再导入。
2. **标准 CSV 导出**(明文,带强警示):用于迁移到其它密码管理器。

## 任务详情
### 9.1 加密备份导出 / 导入
- [ ] 设计备份文件格式:沿用 `@repo/db` 的 AES-256-GCM 信封,用用户口令派生密钥(如 PBKDF2 / scrypt)加密整库。
- [ ] 导出:`expo-file-system` 写文件 + 系统分享/保存。
- [ ] 导入:选择备份文件 → 输入口令 → 校验解密 → 合并/覆盖入库(复用现有 `addPasswords`)。
- [ ] 合并策略:去重(按 title+username+url),冲突提示。

### 9.2 CSV 导出(明文)
- [ ] 导出标准列(title,username,password,url,notes)的 CSV。
- [ ] 强制二次确认 + 明确警示「文件未加密」。
- [ ] 与 0003 一致:避免明文长期驻留(导出后提示删除)。

## 验收 / 测试标准
- [ ] 导出加密备份 → 卸载重装 / 换机 → 导入还原,数据一致。
- [ ] 错误口令导入被正确拒绝。
- [ ] CSV 可被主流密码管理器(或自家 AI 导入)正确读取。
- [ ] 导入合并不产生重复或数据错乱。
